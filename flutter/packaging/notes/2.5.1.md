Songs from YouTube download again.

- When YouTube refuses a download, Nazzil asks again as another of YouTube's apps (Android, VR, iPhone, TV) instead of stopping with "This post blocked the download".
- A paused download carries on from its file only when YouTube hands back the same stream, so a resumed song is never two streams stuck together.
- New for Linux: a Flatpak.

## Which file

| Device | File |
|---|---|
| Android phone | `Nazzil-2.5.1-android-arm64.apk` |
| iPhone | `Nazzil-2.5.1-ios-unsigned.ipa` |
| Windows | `Nazzil-2.5.1-windows-x64-setup.exe` |
| Mac | `Nazzil-2.5.1-macos.dmg` |
| Linux: Ubuntu, Debian | `Nazzil-2.5.1-linux-amd64.deb` |
| Linux: any, with Flatpak | `Nazzil-2.5.1-linux-x86_64.flatpak` |
| Linux: any | `Nazzil-2.5.1-linux-x86_64.AppImage` |

## Installing

- **Android**: if you have 2.4 or older, uninstall it first. This build is signed with a new key that stays, so Android will not install it over those, but later versions install over this one. What you saved to the gallery stays; the list inside Nazzil starts empty.
- **iPhone**: the IPA is unsigned. Install it with SideStore, AltStore or Sideloadly, which sign it with your Apple ID; a free one works. Apple makes such installs expire after 7 days, and SideStore and AltStore renew them.
- **Windows**: the installer is not signed, so SmartScreen may warn. Choose More info, then Run anyway.
- **Mac**: open the disk image and drag Nazzil onto Applications. The app is not notarised: the first time it is blocked, open System Settings, Privacy & Security, and choose Open Anyway.
- **Linux**: install the .deb with `sudo apt install ./Nazzil-2.5.1-linux-amd64.deb`, or the Flatpak with `flatpak install ./Nazzil-2.5.1-linux-x86_64.flatpak`, which fetches its runtime from Flathub the first time. The AppImage runs after `chmod +x`. The .deb and the AppImage need Ubuntu 24.04, Debian 13, Fedora 40 or newer.
